## 2024-04-29 - [Fix XSS vulnerability in HTML templates]
**Vulnerability:** Cross-Site Scripting (XSS) vulnerability found in `index.html`. The application was rendering user-controlled data directly to the DOM using `.innerHTML` without proper sanitization. The data from `data/minis.json` (such as `m.name`, `m.type`, etc.) was being injected in `renderGrid`, `openDetail`, and `setupCarousel`.
**Learning:** Vanilla HTML applications lacking a templating engine or framework often fall victim to XSS vulnerabilities due to manual DOM manipulation via `.innerHTML`. A sanitization step is necessary.
**Prevention:** Avoid using `.innerHTML` with user-supplied data unless strictly required. Use `.textContent` when possible. **Vulnerability:** The `escapeHtml()` function in `editor.html` was missing escaping logic for single (`'`) and double (`"`) quotes. This left the application vulnerable to HTML attribute injection if user-supplied input was placed inside an HTML attribute block, as attackers could break out using quotes.
**Learning:** Proper escaping to prevent XSS must account for all five critical characters: `<`, `>`, `&`, `"`, and `'`. Missing any of these leaves specific injection vectors open, particularly when building raw HTML strings manually.
**Prevention:** Ensure any custom `escapeHtml` implementation replaces all 5 characters (`&`, `<`, `>`, `"`, `'`) with their respective HTML entities to prevent breakout in both element bodies and HTML attributes.
## 2024-05-24 - [Add Content Security Policy headers]
**Vulnerability:** Missing Content Security Policy (CSP) headers, allowing unrestricted execution of inline scripts, styles, and loading of external resources.
**Learning:** Even static HTML sites benefit from a strict CSP. Because this repository doesn't have a backend to serve HTTP headers, `<meta http-equiv="Content-Security-Policy">` tags are an effective alternative.
**Prevention:** Always define a Content Security Policy specifying allowed sources for scripts, images, and styles (e.g., `default-src 'self'`).
## 2024-05-30 - [Fix HTML attribute injection via unescaped single quote in encodeURIComponent]
**Vulnerability:** Cross-Site Scripting (XSS) / HTML Attribute Injection vulnerability. The `PLACEHOLDER_SVG` function was using `encodeURIComponent` to generate an SVG data URI, but `encodeURIComponent` does not encode single quotes (`'`). Because the resulting URI was being inserted into single-quoted HTML attributes (`onerror="this.src='${PLACEHOLDER_SVG}'"`), an attacker could potentially break out of the attribute context if the SVG text contained a single quote.
**Learning:** In JavaScript, `encodeURIComponent()` does not escape the `'` character. When generating data URIs (e.g., SVG data URIs) that will be injected into HTML attributes, failing to manually escape the single quote can lead to injection vulnerabilities.
**Prevention:** Always remember to chain `.replace(/'/g, "%27")` after `encodeURIComponent()` when encoding data that might be placed inside single quotes, or prefer using double quotes for HTML attributes when injecting data URIs, though escaping is the safest defense.
## 2024-06-03 - [Fix ReDoS Vulnerability in editor.html ID Validation]
**Vulnerability:** Regular Expression Denial of Service (ReDoS) vulnerability in `editor.html`. The ID validation regex `/^[a-z0-9]+[a-z0-9-_]*$/` had overlapping capture groups (`[a-z0-9]+` and `[a-z0-9-_]*`). If an attacker provided a long string of matching characters followed by a non-matching character, the regex engine would undergo catastrophic backtracking, consuming excessive CPU and blocking the main thread.
**Learning:** ReDoS vulnerabilities often occur when overlapping quantifiers exist in regex patterns. Even local client-side validation can be exploited to cause a denial of service if an attacker provides a crafted input file or payload.
**Prevention:** Always check regular expressions for overlapping capture groups and potential catastrophic backtracking. Use tools to analyze regex complexity. Fix overlapping patterns by ensuring mutual exclusivity or simplifying the pattern (e.g., using `/^[a-z0-9][a-z0-9-_]*$/` instead).

## 2024-06-27 - [Fix Prototype Pollution / DoS Vulnerability in sortMinis]
**Vulnerability:** A Denial of Service (DoS) vulnerability existed in `index.html` within the `sortMinis` function. The code used a dynamic object lookup (`const get = { ... }[by]`) to retrieve a sorting function based on user input `by`. If an attacker provided a prototype key (e.g., `"__proto__"` or `"constructor"`), the lookup would return an object or the Object constructor instead of a sorting function. Since `Array.prototype.sort()` expects either a function or `undefined`, passing this object would throw a `TypeError`, crashing the script and disrupting functionality.
**Learning:** Object lookups using unvalidated user input are susceptible to prototype pollution and unexpected property retrieval. If the retrieved value is passed to a method expecting a specific type (like a function for `.sort()`), it can cause uncaught exceptions and application crashes.
**Prevention:** When retrieving functions from an object lookup using user-controlled keys, always verify the result is a function (e.g., `typeof func === "function"`) before invoking or passing it to methods like `Array.prototype.sort()`. Alternatively, use `Object.create(null)` for the lookup map to avoid inheriting prototype properties.
